# ThetOS vs FreeRTOS: compile-time comparison of the same mistakes

Generated by `run_all.sh`. Each row is one mistake, written for a FreeRTOS firmware task and for a ThetOS task.

Two groups: the kernel APIs compared directly, then the driver layers (ThetOS typestate drivers against ST's HAL).

## Kernel level

FreeRTOS kernel API against the ThetOS kernel API (`System::spawn_task`, `execute_in_critical_section`).

| Case | Mistake | FreeRTOS kernel (C) | ThetOS (Rust) | Mechanism |
|---|---|---|---|---|
| `task_returns` | A task function returns (task body with no loop, passed to `xTaskCreate`) | compiles (0 warnings, 0 errors) | does not compile: `E0308` mismatched types; correct form compiles | type: the entry point must be `-> !` |
| `swapped_args` | Priority and stack size swapped (`xTaskCreate(..., 1, NULL, configMINIMAL_STACK_SIZE, NULL)`) | compiles (0 warnings, 0 errors) | does not compile: `E0308` arguments to this method are incorrect; correct form compiles | type: `TaskPriority` and the stack size are different types |
| `critical_section` | Critical section entered but not exited on every path (`taskENTER_CRITICAL()` then an early `return`) | compiles (0 warnings, 0 errors) | not expressible; the correct form compiles | not expressible: only the closure form exists, so there is no failing program to write |
| `shared_state` | Two tasks share a plain variable (plain `static unsigned short` written and read by two tasks) | compiles (0 warnings, 0 errors) | does not compile: `E0277` `Cell<u16>` cannot be shared between threads safely; correct form compiles | language: a shared static must be `Sync` (Rust, not ThetOS design) |

## Driver level

ST's STM32L1 HAL (used with FreeRTOS, which ships no peripheral layer) against ThetOS's typestate drivers.

| Case | Mistake | FreeRTOS + STM32 HAL (C) | ThetOS (Rust) | Mechanism |
|---|---|---|---|---|
| `wrong_mode` | Write to a pin configured as an input (`HAL_GPIO_Init` as input, then `HAL_GPIO_WritePin`) | compiles (0 warnings, 0 errors) | does not compile: `E0599` no method named `set` found for struct `nucleo_l152re::Pin<PORT, PIN_INDEX, MODE>` in the current scope (the type is `nucleo_l152re::Pin<PortA, 6, Input>`); correct form compiles | typestate: `set()` exists only on output pins |
| `stale_handle` | Reuse a handle after it changed state (`HAL_UART_DeInit`, then `HAL_UART_Transmit` on the same handle) | compiles (0 warnings, 0 errors) | does not compile: `E0382` use of moved value: `serial`; correct form compiles | ownership: `into_active()` consumes the old UART handle |
| `uart_before_init` | Use a UART that was never initialised (`HAL_UART_Transmit` with no `HAL_UART_Init`) | compiles (0 warnings, 0 errors) | does not compile: `E0599` no method named `write_byte` found for struct `Serial<MODE>` in the current scope (the type is `Serial<nucleo_l152re::uart::Uninit>`); correct form compiles | typestate: `write_byte()` exists only on an active UART |
| `pwm_before_active` | Use a PWM channel before the timer is activated (`HAL_TIM_PWM_Start` with no `HAL_TIM_PWM_Init`) | compiles (0 warnings, 0 errors) | does not compile: `E0599` no method named `channel1` found for struct `Pwm<Tim3, nucleo_l152re::pwm::Uninit>` in the current scope (the type is `Pwm<Tim3, nucleo_l152re::pwm::Uninit>`); correct form compiles | typestate: `channel1()` exists only on an active PWM timer |

Every ThetOS failure has a passing control (the `ok_*` fixture in `thetos/src/lib.rs`): the same operation in the correct state compiles.

## Where ThetOS does not differ

- Task arguments are type-erased in both (`void *` vs `*mut ()`).
- Priority and stack-size checks are runtime checks in both.
- Stack overflow is detected at runtime in both (FreeRTOS `configCHECK_FOR_STACK_OVERFLOW`, ThetOS canary guard).
- Reusing one physical pin through two handles still compiles in ThetOS (ADR-0008).
- The shared-state row comes from the Rust language, not from the ThetOS design.
